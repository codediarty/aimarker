동작 방식

원본은 그 자리에, 근거와 서명만 오갑니다

판정 규칙과 생성 도구 지문은 서버에만 있고, 파일을 읽는 판독기는 공개되어 있습니다. 같은 파일이면 어디서 불러도 같은 판정이 나옵니다.

  1. 이 기기에서 판독출처 판독기 aim-extract 가 파일을 읽어 특징값(features)과 서명 검증용 조각(pack)을 만듭니다. 원본 · 픽셀 · 글 원문은 보내지 않습니다.
  2. 서버가 판정am.analyze: C2PA 서명 재검증 · 생성 기록 · 도구 지문으로 AI 사용 여부(used · not_used · unknown), 근거 등급, 고를 수 있는 표시(allowed)를 정합니다.
  3. 근거 맞춤 발급am.mark: 근거와 맞지 않는 표시는 막고(CONFLICT), 마크마다 Ed25519 로 서명(JWS)해 원장에 남깁니다.
  4. 누구나 확인공개키로 서명 확인, 마크 확인 쪽 · QR · 삽입 배지, 하루치 원장은 다음 날 OpenTimestamps 공개 앵커로.

SDK 1.1

파일 하나로 붙이는 JavaScript · Python 클라이언트

의존성이 없습니다. JavaScript SDK 에는 출처 판독기가 들어 있어 파일 바이트를 그대로 넘기면 됩니다. Python SDK 는 글 · 서명 확인을 표준 라이브러리로 하고, 파일 판독은 Node.js 로 합니다. 서버 쪽 코드에서 사용하고 API 키는 환경 변수에 두세요.

aimarker.mjs · Node 20+ · Deno · Bun · Workers
import { AIMarker } from './aimarker.mjs';
import { readFile, writeFile } from 'node:fs/promises';
const am = new AIMarker({ key: process.env.AIMARKER_KEY });

const bytes = await readFile('banner.jpg');
const a = await am.analyzeFile(bytes, { name: 'banner.jpg' });
console.log(a.verdict);   // { ai: 'used', scope: 'edited', basis: 'verified', allowed: [...], suggest: 'ai_edited' }

try {
  const m = await am.mark({ bytes, name: 'banner.jpg' }, { label: 'auto', title: '봄 신상 배너' });
  console.log(m.id, m.url, m.key);   // 관리 키(m.key)는 한 번만 나옵니다
  const marked = AIMarker.embedMark(bytes, m);   // 파일 안에 마크 번호 · 서명
  await writeFile('banner.aimarker.jpg', marked);
  await am.markEdit(m.id, m.key, { alt: [await AIMarker.sha256(marked)] });   // 표시본 등록
} catch (e) {
  if (e.code === 'DECLARE') { /* 근거 없음: 사용자에게 AI 사용 여부를 물어 label 로 */ }
  if (e.code === 'CONFIRM') { /* 비슷한 AI 이미지가 있음: 확인받고 confirm: true 로 */ }
}

import { AIMarker } from './aimarker.mjs';
const am = new AIMarker({ key: process.env.AIMARKER_KEY });

export async function onProductImages(files, seller) {   // files: [{ bytes, name, sku }]
  const r = await am.markBatch(files.map((f) => ({ bytes: f.bytes, name: f.name, ref: f.sku, label: 'auto' })), { issuer: seller });
  for (const x of r.results) {
    if (x.ok) await db.saveMark(x.ref, { id: x.id, url: x.url, label: x.label, basis: x.basis, key: x.key });
    else if (x.code === 'DECLARE') await askSeller(x.ref);   // 기록 없는 이미지: 판매자 신고로 발급
  }
}
폴더 · 여러 파일을 20건씩 확인하고 리포트(HTML · CSV)로 · SDK 1.1
import { AIMarker, report } from './aimarker.mjs';
import { readdir, writeFile } from 'node:fs/promises';

const am = new AIMarker({ key: process.env.AIMARKER_KEY });
const dir = './upload/2026-10';
const files = (await readdir(dir)).filter((f) => /\.(jpe?g|png|webp|mp4|pdf)$/i.test(f)).map((f) => dir + '/' + f);

// 20건씩 나눠 동시에 3묶음 확인(원본은 보내지 않음 · 발급하지 않음)
const entries = await am.analyzeFiles(files, { onProgress: (n, all) => console.log(n + '/' + all) });
const R = report.build(entries, { org: '우리 쇼핑몰' });
console.log(report.summaryText(R));          // 바로 표시 가능 비율 · 확인할 점 · 주요 도구
await writeFile('report.html', report.html(R)); // 혼자 열리는 리포트(인쇄 · PDF 가능)
await writeFile('report.csv', report.csv(R));   // 파일마다 판정 · 근거 등급 · 고를 수 있는 표시

에이전트 지침

AI에게 이렇게 일러 두세요

맞춤 GPT · Claude 프로젝트 · 사내 에이전트의 지침(system prompt)에 붙여 넣으면 됩니다.

지침
이미지 · 영상 · 오디오 · 글을 사용자에게 넘기거나 게시하기 전에 aimarker_analyze_file(글은 aimarker_analyze_text)로 AI 사용 근거를 확인한다.
- 표시가 필요하면 aimarker_mark 로 마크를 받는다. 파일에 근거가 있으면 label 을 auto 로 둔다.
- 표시는 verdict.allowed 안에서만 고른다. 근거가 없으면 사용자에게 실제 AI 사용 여부와 사용한 도구를 묻고, 그 답으로 발급한다.
- 이 대화에서 내가 만들거나 고친 콘텐츠는 AI 사용 표시를 고르고 tools 에 사용한 AI를 적는다. AI 미사용(no_ai)은 사용자가 그렇다고 말했을 때만 고른다.
- CONFIRM 이 오면 내용을 사용자에게 보여 주고, 확인했을 때만 confirm: true 로 다시 보낸다. CONFLICT 면 allowed 에서 다시 고른다.
- 관리 키(mk_…)는 한 번만 나오니 사용자에게 안전하게 보관하라고 알린다.
- 마크가 법적 인증이라고 말하지 않는다. 판정 정확도를 숫자로 말하지 않는다.
- 광고 문구를 쓰면 aimarker_check 로 검수하고, 결과는 "위험 후보"와 근거 법령으로 설명하며 법률 자문이 아님을 알린다.

표시 · 근거

label: ai_generated · ai_edited · ai_assisted · no_ai. basis: verified(서명 검증) · record(파일 기록) · declared(발급자 신고). 근거와 맞지 않는 표시는 CONFLICT, 비슷한 이미지 · 표시본에 AI 마크가 있으면 CONFIRM.

인증 · 한도

본문에 "key": "amk_…". 무료 키는 하루 300회(일괄은 항목 수만큼). 마크 확인 · 찾기 · 공개키 · 앵커는 키 없이, 마크 관리는 관리 키만으로 됩니다. 한도 상향은 상담.

오류

ok:false 와 code: KEY · QUOTA · BUSY · HASH · CONFLICT(allowed · reasons) · CONFIRM(related) · DECLARE · REVOKED · NOT_FOUND. 전체 설명은 llms-full.txt.

서명 확인

AIMarker 서버에 묻지 않고 마크를 확인하는 법

마크마다 붙는 서명(cred)은 JWS(EdDSA · Ed25519)입니다. 공개키는 /.well-known/aimarker-keys.json 에 있고, 표시본 파일 안(XMP aimarker:Credential)에도 들어 있습니다. 서명이 맞으면 그 마크 번호 · 표시 · 근거 · 원본 해시를 AIMarker가 발급했다는 뜻입니다.

Web Crypto 만으로
const b64u = (x) => Uint8Array.from(atob(x.replace(/-/g, '+').replace(/_/g, '/')), (c) => c.charCodeAt(0));
const [h, p, s] = cred.split('.');
const head = JSON.parse(new TextDecoder().decode(b64u(h)));            // { alg: 'EdDSA', typ: 'JWT', kid: 'amk1-…' }
const { keys } = await fetch('https://aimarker.kr/.well-known/aimarker-keys.json').then((r) => r.json());
const jwk = keys.find((k) => k.kid === head.kid);
const key = await crypto.subtle.importKey('jwk', jwk, { name: 'Ed25519' }, false, ['verify']);
const ok = await crypto.subtle.verify({ name: 'Ed25519' }, key, b64u(s), new TextEncoder().encode(h + '.' + p));
const claims = JSON.parse(new TextDecoder().decode(b64u(p)));         // sub · label · basis · sha256 · at · ledger …
  1. 서명이 맞는지: 머리의 kid 와 같은 공개키로 머리.내용 을 확인합니다.
  2. 내용이 마크와 같은지: sub(마크 번호) · label · basis · sha256 을 am.markinfo 와 맞춰 봅니다. 표시를 바꾸면 새 서명이 나오고 upd 가 붙습니다.
  3. 파일이 같은지: 가진 파일의 SHA-256 이 sha256(원본) 또는 alts(발급자가 등록한 표시본)와 같은지 봅니다.
  4. 철회됐는지: am.markinfo 의 status 가 revoked 이면 더는 유효하지 않습니다.
  5. 언제 기록됐는지: ledger(원장 번호)로 am.anchor 를 불러 그날 공개 앵커에 들어 있는지 봅니다.

const AIMARKER_URL = 'https://script.google.com/macros/s/AKfycbw3ZPLXHv92tfNVs7caH-Bf1OvMesqh0RfR8y4LCsT5DaE3otEbGWhyFLIY6FqoBEY/exec';

/**
 * 마크 번호로 현재 표시 · 근거 · 상태. 예: =AIMARKER_MARK(A2)  → "AI 생성 · 파일 기록 · 유효"
 * @customfunction
 */
function AIMARKER_MARK(id) {
  if (!id) return '';
  const res = UrlFetchApp.fetch(AIMARKER_URL, { method: 'post', contentType: 'text/plain', muteHttpExceptions: true,
    payload: JSON.stringify({ action: 'am.markinfo', id: String(id).trim() }) });
  const r = JSON.parse(res.getContentText());
  if (!r.ok) return '오류: ' + r.message;
  return r.labelKo + ' · ' + r.basisKo + ' · ' + (r.status === 'revoked' ? '철회됨' : '유효');
}
  1. 파일이 들어오는 곳(쇼핑몰 · CMS · 드라이브)에서 내 서버의 작은 함수로 넘깁니다. 이 함수가 SDK 로 markBatch 를 부릅니다(파일 판독은 서버에서).
  2. 결과의 ok 이면 마크 번호 · 확인 주소를 상품 · 기사 데이터에 저장하고, 배지를 페이지에 붙입니다.
  3. DECLARE(기록 없음)면 판매자 · 기자에게 AI 사용 여부를 묻는 알림을 보내고, 답으로 am.mark 를 부릅니다.
  4. n8n 의 HTTP Request 노드는 Follow Redirects 를 켜고 Body 를 Raw · text/plain 으로 보냅니다. 마크 확인(am.markinfo)은 키 없이 됩니다.
